# Composed automation rollout

## Why
The operator approved analysis, a complete plan and sequential implementation of online multi-session supervision, event triggers informed by pi-routines, and durable operation informed by pi-reactor. The delivered timer foundation is necessary but does not establish an installed end-to-end supervisor.

## What Changes
- Stage B: provide bounded supervisor prompt/guide, fixed installation artifacts and isolated two-peer end-to-end verification using existing tools.
- Stage C: add optional event admission with bounded dedup, pause, daily limits and explicit missed-event policy without duplicating schedules.
- Stage D: add durable intent/claim, native supervisor host/service lifetime, existing-run reconciliation and bounded safe failure/outbox behavior.
- Keep one roadmap and explicit source/fixture/install/live status; use existing Intercom, Subagents and Messenger ownership.

## Impact
Primary owner is this fork. Other repositories change only for proven missing public interfaces. No forced business-session reload, new credential store, arbitrary public event execution, new approval ledger, model routing change or external exactly-once promise. Real pilot goals/peers must be concrete; unblocked implementation proceeds independently.
